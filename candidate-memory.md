## Add "missing/flashing activity bar icon" gotcha to vsix-webview-debugging skill (2026-08-20 12:15)

Component type: skill
Suggestion: In `Agentic-OS/Library/Skills/vscode/vsix-webview-debugging/SKILL.md` (Gotchas section), add an entry for the failure mode where a webview-view extension's activity bar icon is completely absent (not even listed, unchecked, in the activity-bar right-click menu) or flashes on then vanishes after "Developer: Reload Window" — even after full uninstall/reinstall of the VSIX. Root cause: VS Code persists per-workspace view-layout state (including `isHidden` for the view and `visible` for the container) in `state.vscdb`, keyed by view/container id, independent of the extension install. This state survives extension uninstall/reinstall and can get stuck from an earlier session (e.g. one where the extension errored while loading). Fix: run Command Palette → "View: Reset View Locations" to clear stuck hidden/moved state back to defaults. This should be checked before chasing manifest bugs, AV/EDR interference, or extension-host activation errors.
Reason: In this session, diagnosing a missing activity-bar icon for the exact extension this skill documents as its "Working example" took a long detour through CrowdStrike Falcon theories, Extension Development Host window confusion, and VS Code profile theories, none of which panned out — while the manifest, build, and installed files were valid the entire time. The actual fix ("View: Reset View Locations") is a single fast command that should be tried early for this symptom, and belongs in the skill's Gotchas list since the skill already centers on this project.
